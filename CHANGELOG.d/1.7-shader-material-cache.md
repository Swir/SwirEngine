# SwirEngine 1.7 — Shader & Material Preparation Cache

- added additive `swirengine.shader_cache17` deterministic CPU-side shader/material preparation without changing stable 1.x renderer or material APIs
- canonicalize shader stages, defines and material metadata into SHA-256 source fingerprints that are independent of mapping insertion order
- run optional source preprocessing through the bounded 1.7 background job scheduler while keeping creator finalization/compile callbacks behind an explicit owning-thread `poll()` boundary
- cache only backend-neutral prepared CPU data, with bounded deterministic FIFO retention, exact-fingerprint reuse and payload-free diagnostics
- add generation-based single-source and global invalidation so in-flight products invalidated before compilation are reported as stale rather than finalized
- allow cancellation after worker completion but before owner-thread compilation, isolate creator preprocessor/finalizer failures and retain reusable preparation after compile failure
- add focused tests, creator demo, deterministic 1,024-request workload benchmark and Python 3.10/3.13/3.14 CI coverage
- keep stable 1.x root imports and published 1.5.0 package metadata unchanged; Release/PyPI remain frozen until SwirEngine 2.0
