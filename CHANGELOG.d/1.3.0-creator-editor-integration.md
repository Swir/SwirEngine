# Creator / Editor Integration

- Added a toolkit-neutral `EditorSystemRegistry` for lazy creator-facing diagnostics from SwirEngine 1.3 subsystems.
- Added `CreatorEditorIntegration` / `CreatorEditorFrame` as an additive bridge around the existing `EditorFrontendController`; hierarchy, inspector, viewport, assets, console, profiler and playtest remain on their established 1.x paths.
- Added deterministic category/query filtering before diagnostics-provider invocation so hidden/unrelated systems are not polled by a filtered editor frame.
- Added support for dataclass diagnostics, mappings, plain public-attribute objects and explicit derived providers.
- Added a creator example, focused regression coverage and a 10,000-system locality benchmark requiring a one-category frame to invoke exactly 100 providers.
- No game-frame polling is introduced when the editor systems snapshot is not requested.
- This milestone does not create a separate 2.0 editor, visual shader graph, terrain editor or navmesh painting tool.
