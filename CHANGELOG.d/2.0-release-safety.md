# SwirEngine 2.0 release safety candidate

- Add deterministic staged-export integrity verification over the existing export inventory/checksums, including portable-path validation, cross-platform case-collision rejection, unexpected/missing file detection and generated native-spec hashing.
- Add an explicit `swir-build-integrity.json` seal with a reproducible build identity derived from the exact export manifest, staged file checksums and generated build inputs.
- Add support-bundle verification that accepts only generated diagnostics, validates ZIP/report hashes and fingerprints, locks opt-in privacy declarations, rejects injected/unsafe entries and can require the report to match an expected verified build identity.
- Add focused regressions, a deterministic failure-injection verifier, documentation and a Python 3.10/3.13/3.14 CI gate.
- Keep published SwirEngine 1.4.0/1.5.0 history unchanged; no release, tag or PyPI publication is part of this source-development milestone.
