## SwirEngine 1.8 — Visibility & LOD Submission 3.0

- Added opt-in `swirengine.visibility18` with finite 2D/3D AABB contracts and a bounded deterministic uniform-grid candidate index.
- Added explicit item/cell/query/candidate limits, atomic register/replace behavior, stable creator-facing failure codes, portable registry/query diagnostics and SHA-256 state fingerprints.
- Added deterministic cross-frame LOD selection with creator-configurable thresholds, hysteresis, bounded session state and optional creator-owned LOD policy hooks.
- Added optional tag/predicate filtering so render backends can layer frustum, portal, room, occlusion-result or gameplay visibility rules over the conservative spatial candidate set without coupling the core to a GPU backend.
- Added stable visible-submission ordering for later renderer integration plus focused/hardening regressions, creator documentation/demo and a deterministic 12,000-item / 120-query workload gate.
- Kept all stable 1.x renderer/scene behavior unchanged unless creators explicitly opt into the new 1.8 visibility layer.
