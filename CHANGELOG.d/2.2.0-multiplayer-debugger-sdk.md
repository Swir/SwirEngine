## SwirEngine 2.2 M9 source development

- Added bounded ping/pong round-trip measurement with private monotonic timing, strict packet
  validation, hard pending/sample limits and privacy-safe aggregate diagnostics.
- Added deterministic ASCII multiplayer snapshots and captures over the production session,
  replication, profiler and transport systems, with opaque aliases, allowlisted numeric counters
  and a hard 2 MiB capture limit.
- Added a transient SwirEditor multiplayer debugger controller with explicit attach/detach and
  project-confined atomic capture export under `.swir`; diagnostics never participate in normal
  project dirty/save/reopen state.
- Added an explicit trusted-installed Python extension SDK with capability-gated, immutable and
  bounded declarative panels/actions. It deliberately provides no discovery, autoload,
  `PluginManager` bridge or raw editor/runtime objects, and it is not an operating-system sandbox.
- Added the dynamic Tk extension host and a built-in multiplayer debugger adapter with sanitized
  lifecycle/action failures and fail-closed cleanup.
- Hardened project and desktop export so case-insensitive `.swir` editor state cannot ship through
  broad includes, direct includes, entrypoints, icons or symlink aliases, and unsafe sources fail
  before previous output cleanup.
- Added CPython 3.10/3.13/3.14 regression coverage, a real localhost TCP RTT check, isolated
  installed-package relocation and native Tk/Xvfb lifecycle qualification.

This is source-development work. It does not mark M9 accepted, publish SwirEngine 2.2, fabricate
latency from configured impairment values or claim physical-network or hardware performance.
