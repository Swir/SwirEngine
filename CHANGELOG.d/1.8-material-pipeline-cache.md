# SwirEngine 1.8 — Material Submission & Pipeline State Cache

- add immutable backend-neutral `PipelineStateKey` and `MaterialKey` identities with deterministic SHA-256 fingerprints;
- add bounded `MaterialSubmissionQueue` planning that clusters reorderable draws while preserving explicit order barriers for transparent/UI/post-process-sensitive work;
- add portable submission diagnostics covering authored/compiled pipeline and material switches;
- add generic bounded deterministic LRU `PipelineStateCache` with shader invalidation, retryable clear/close behavior, and backend create/destroy failure containment;
- add plan preparation, creator demo, hardening tests, documentation, and an 81,920-draw deterministic workload regression gate;
- keep SwirEngine 1.8 source-only with Release/PyPI frozen until SwirEngine 2.0.
