## Hot-reload rollback hardening

- added `HotReloadStateRegistry.restore_atomic()` for all-or-nothing restoration across multiple state providers and domains
- added `HotReloadStateDomain.restore_atomic()` with the same domain-boundary validation as scoped capture/restore
- pre-capture every participating provider's rollback baseline before applying any requested mutation, preventing partial updates when rollback state itself cannot be captured
- restore touched providers in reverse order when any callback fails, including the failing provider because callbacks may mutate before raising
- surface combined diagnostics when the original restore and rollback both fail instead of silently hiding the second failure
- make plugin hot reload use transactional restore automatically when preserving multiple providers/domains while retaining legacy single-provider callback behavior for compatibility
- added regression coverage for cross-domain rollback, preflight capture failures, rollback failures, domain isolation and non-strict missing providers
- package version remains `0.4.22`; this is compatible hardening rather than a release-boundary change
