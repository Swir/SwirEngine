## 1.4.0

SwirEngine 1.4.0 completes the **Production World & Engine Power** roadmap at **10/10 = 100.0%**.

- completed generated terrain, chunked world LOD and large-world streaming integration;
- completed Physics 2.0 plus production first-person, third-person and platformer character controllers;
- completed opt-in Renderer 2.0 with cascaded directional shadows, depth/view-normal prepass, SSAO, HDR bloom and decals;
- completed OpenGL 3.3 GPU particle/VFX paths for sprites, textures, trails and instanced meshes;
- completed Asset Pipeline 2.0 with dependency fingerprints, transitive invalidation, persistent derived caching, glTF dependency processing and conservative optimization;
- completed scalable scene acceleration with deterministic static BVH, dynamic refits, Renderer2 candidate views and CPU/GPU Hi-Z foundations;
- completed Editor Authoring Power with multi-selection, grouped edits, transaction-safe undo/redo, specialized inspector adapters, Play/Edit isolation and the opt-in `swirengine.editor14` facade;
- completed Multiplayer 2.0 foundations with replicated schemas, snapshots/deltas, interpolation, client prediction/reconciliation, bounded server rewind and bandwidth diagnostics;
- added the integrated asset-free `Neon Frontier 1.4` release-validation project covering the complete 1.4 system surface in headless, real OpenGL and packaged Windows modes;
- synchronized package/runtime version metadata, README, release notes and the locked 100% roadmap to `1.4.0`;
- added a strict tag-only `v1.4.0` publication pipeline that reruns full tests, lint, compile, deterministic performance contracts, real OpenGL smoke, packaged Windows probing, clean wheel checks and the native Windows CPython 3.14 wheel path before Trusted Publishing to PyPI;
- added post-publication clean installs from public PyPI on Linux/Python 3.13 and Windows/Python 3.14 before the release workflow is considered complete;
- preserved the established stable 1.x compatibility surface and kept the locked 1.3 regression game/workflow active as a compatibility gate.

Publication remains separate from source completion: the `v1.4.0` tag, PyPI upload and GitHub Release may only be created after the final 10/10 branch passes the complete release-candidate matrix.
