## SwirEngine 1.2 gameplay networking

- Added `GameplaySession` as a deterministic, thread-free gameplay protocol layered over the existing 1.x TCP transport.
- Added named `GameplayMessage` events and ordered `MessageRouter` dispatch.
- Added explicit `RPCRegistry`, request/response helpers and bounded completed-result buffering without exposing arbitrary Python callables to remote input.
- Added `ConnectionState`, session error tracking and `NetworkDiagnostics` counters for packets, messages, RPC activity, unknown methods/messages and state transitions.
- Added socket-pair regression coverage, creator documentation and a runnable gameplay networking example.
- Existing `NetworkPacket`, `TCPPeer`, `TCPClient` and `TCPServer` APIs remain compatible.
